## Question 1: What are we working on?

### Scope and exclusions

This model covers only the Milestone 2 workstation and GitHub-hosted pull-request fixture. It covers the Docker client and daemon context, Compose model, local operator command, generated local credentials and provenance journal, lifecycle lock, Kratos migration and SQLite volume, SpiceDB memdb bootstrap, internal probe, loopback test surfaces, container registry inputs, exact-resource reset, and retained compatibility evidence.

The profile uses reserved `.invalid` identities and opaque authorization fixtures. It is not a consuming application and has no protected product operation. A SpiceDB deny therefore proves only component semantics, not application-level fail-closed authorization.

Production packaging, production databases, nonlocal exposure, TLS termination, public control-plane APIs, canonical identity or authorization models, Kratos self-service flow design or disablement, real personal data, audit and retention policy, exact residency domains, and regulatory compliance evidence are excluded. The [residency Product Contract](../plans/2026-08-14-1804-feat-global-realm-data-residency-plan.md) governs their future responsibility boundary and requires this fixture to make no production residency claim.

### Accepted residual risks

No residual risk is accepted at the design-only U1 gate. T10 is the expected candidate: a trusted local Docker administrator can inspect containers and join their networks. U5 must either record a complete acceptance with reviewed evidence, bounded impact, compensating controls, and a re-review trigger, or leave the profile's security conclusion open. Production, shared-host, remote-daemon, personal-data, and residency use cannot be accepted under this model.
